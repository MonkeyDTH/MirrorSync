# 目录同步工具（File Sync）设计方案

**日期**：2026-08-13
**状态**：已实现（2026-08-14 变更同步模式）

---

## 变更记录

- **2026-08-14**：同步模式由「镜像同步」改为「仅新增/更新，不删除」。原因：镜像模式会删除输出目录中输入目录没有的文件，用户反馈这不是期望行为，输出目录里的额外文件应当保留。相应移除了 `sync.rs` 中的镜像清理逻辑与 `SyncResult.deleted` 字段。

## 一、背景与动机

需要一个 Windows 桌面小工具：维护多组「输入目录 → 输出目录」的目录对，用户可以勾选其中若干对，一键将输入目录的内容同步到输出目录。用 Tauri 开发，兼顾体积小、性能好、界面美观。

关键决策：
- 同步模式：**仅新增/更新**，只复制输入目录中新增或有变化的文件，输出目录中多出来的文件不会被删除（详见变更记录）。
- 触发方式：**纯手动**，用户勾选目录对 → 点击"开始同步" → 一次性执行，不做自动监听（后续可迭代）。
- 技术栈：**Tauri 2 + React + TypeScript + Tailwind CSS + shadcn/ui**。

## 二、方案设计

### 2.1 整体架构

```
┌─────────────────────┐        invoke/emit        ┌──────────────────────┐
│  React 前端 (UI)     │  <───────────────────────>  │  Rust 后端 (Tauri)   │
│  目录对管理/勾选/展示 │                              │  文件系统同步/配置持久化 │
└─────────────────────┘                              └──────────────────────┘
```

同步的重活（遍历、比较、复制、删除）放在 Rust 侧执行，前端只负责 UI 展示与触发，通过 Tauri `invoke` 调用命令，同步过程中用 `emit` 推送进度事件。

### 2.2 数据模型

```rust
// src-tauri/src/config.rs
struct SyncPair {
    id: String,        // uuid
    name: String,       // 用户备注名，可为空，为空时用目录名展示
    source: String,     // 输入目录绝对路径
    target: String,     // 输出目录绝对路径
    selected: bool,      // 是否勾选参与本次同步（持久化，记住上次选择）
}
```

配置整体存为 JSON：

```json
{
  "pairs": [
    { "id": "...", "name": "项目A", "source": "D:\\A\\src", "target": "E:\\Backup\\A", "selected": true }
  ]
}
```

存储位置：Tauri `app_config_dir()`（Windows 下类似 `%APPDATA%/com.yotta.filesync/config.json`），启动时读取，任何增删改立即写回。

### 2.3 同步逻辑（核心）

对每个被勾选的目录对，执行 `sync_pair(source, target)`：

1. **校验**：source 必须存在且是目录；target 不存在则自动创建；source == target 或存在包含关系则报错跳过（防止递归复制自身）。
2. **遍历 source**（递归 `walkdir`），构建相对路径列表 `source_files`。
3. **复制/更新**：对每个文件，若 target 中对应文件不存在，或存在但 `size`/`mtime` 与 source 不同，则复制覆盖（保留目录结构，必要时 `create_dir_all`）。输出目录中源目录没有的文件**不做任何处理**，原样保留。
4. **单文件错误不中断整体**：某个文件复制失败（占用、权限等）记录到结果日志，继续处理其余文件；目录级错误（source 不存在等）则该目录对整体标记失败。
5. **进度反馈**：处理过程中按文件粒度 `emit("sync-progress", {pair_id, current_file, done, total})`，前端可展示进度条/当前文件名。

同步结果结构：

```rust
struct SyncResult {
    pair_id: String,
    copied: u32,
    skipped: u32,     // 未变化跳过的文件数
    errors: Vec<String>, // 具体失败文件及原因
    duration_ms: u64,
}
```

多个目录对之间**顺序执行**（避免磁盘 IO 争抢导致进度展示混乱），完成一个再进行下一个。

### 2.4 前端 UI

页面整体一个单页即可，布局：

```
┌──────────────────────────────────────────────┐
│  目录同步工具                        [+ 添加目录对] │
├──────────────────────────────────────────────┤
│ [√] 全选   已选 2/3               [开始同步▶] │
├──────────────────────────────────────────────┤
│ ┌────────────────────────────────────────┐   │
│ │ ☑ 项目A                      [编辑][删除] │   │
│ │   📁 D:\A\src  →  📁 E:\Backup\A         │   │
│ └────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────┐   │
│ │ ☐ 项目B                      [编辑][删除] │   │
│ │   📁 D:\B\src  →  📁 E:\Backup\B         │   │
│ └────────────────────────────────────────┘   │
├──────────────────────────────────────────────┤
│ 同步日志/结果面板（同步时展开，可折叠）           │
└──────────────────────────────────────────────┘
```

- **目录对卡片**（`PairCard`）：勾选框、名称、source→target 路径、编辑、删除。使用 shadcn/ui `Card` + `Checkbox`。
- **添加/编辑弹窗**（`PairDialog`）：名称输入框 + 两个"选择目录"按钮（调用 `tauri-plugin-dialog` 的 `open({directory: true})`）+ 保存/取消。
- **同步按钮**：禁用态（无勾选时）、加载态（同步中显示 spinner + 禁止重复点击）。
- **同步日志面板**：同步开始后自动展开，实时显示每个目录对的进度条与当前处理文件；完成后显示汇总（复制 N、跳过 N、耗时、错误列表，错误用醒目颜色标出）。
- 全局用 `sonner`（shadcn 集成的 toast）做轻量提示（如"配置已保存""同步完成"）。

### 2.5 关键交互流程

1. 首次启动：读取配置，若为空显示空状态引导"添加你的第一个目录对"。
2. 添加目录对：弹窗选择两个目录 → 校验非空、不重复、source≠target → 写入配置 → 列表刷新。
3. 勾选若干目录对 → 点击"开始同步" → 前端调用 `invoke('sync_pairs', {pairIds: [...]})` → 监听 `sync-progress` 事件更新进度 UI → 调用返回后展示汇总结果。
4. 编辑/删除目录对：仅改配置，不涉及文件系统。

## 四、验证方式

1. `npm run tauri dev` 启动应用。
2. 手动测试：
   - 添加 2~3 组目录对（可用临时测试目录，一侧放若干文件/子目录）。
   - 只勾选部分目录对同步，确认未勾选的不受影响。
   - 同步后确认：输入目录的文件被正确复制到输出目录；输出目录中原有的、输入目录没有的文件**保留不被删除**。
   - 修改输入目录文件后重新同步，确认增量更新生效（未变化文件不重复复制，可通过修改时间观察）。
   - 测试异常场景：输入目录不存在、source 是 target 的父目录（应报错拒绝）。
3. 关闭应用重新打开，确认目录对列表与勾选状态被正确恢复（配置持久化生效）。
