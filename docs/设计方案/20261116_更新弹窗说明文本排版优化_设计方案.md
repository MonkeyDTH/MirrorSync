# 更新弹窗说明文本排版优化

**创建时间**: 2026-11-16 13:05
**背景**: 更新弹窗把 Markdown 格式的更新说明当纯文本显示，`##`、`- `、`**` 这些符号都露了出来；GitHub 对比链接太长，撑出了横向滚动条。

---

## 1. 问题根因

`latest.json` 的 `notes` 直接使用 `release-notes.md` 全文。这份说明是为 GitHub Release 页面写的 Markdown，而弹窗用 `whitespace-pre-wrap` 原样显示文本。

**关键约束**：用户看到的弹窗是**本机已安装的旧版本**渲染的，`notes` 文本则是每次从线上读取的。

- 只改弹窗代码：要等用户装上新版本后，下一次更新时才能看到效果。
- 改 `notes` 文本：所有旧版本（包括 v0.4.0、v0.4.1）立刻生效。

所以两层都要改，而且**文本层优先**。

## 2. 方案

### 2.1 文本层：清单使用适合纯文本显示的说明（`scripts/updater-manifest.mjs`）

生成 `notes` 时，把 Markdown 转成纯文本也好看的格式：

| 原文 | 转换后 | 理由 |
|---|---|---|
| `## 问题修复` | `问题修复` | 在旧弹窗里，`##` 是噪音 |
| `- 内容` | `• 内容` | 圆点在纯文本里也是清楚的列表样式 |
| `**完整对比**：https://…` | 删除 | 应用内用不上，而且是撑出横向滚动条的元凶 |

旧版本的弹窗效果（`pre-wrap` 显示）：

```
问题修复

• 子目录无读取权限时漏同步却显示成功
• 同步大量文件时窗口无响应
```

**不改 `release-notes.mjs`**：GitHub Release 页面仍然需要 Markdown 和对比链接，只在生成清单时转换。

### 2.2 渲染层：新弹窗按分组排版（`src/components/UpdateDialog.tsx`）

把 `notes` 按行解析：以 `• ` 开头的是条目，其他非空行是分组标题，空行忽略。

```
┌────────────────────────────────────┐
│ 发现新版本 v0.4.2              ×   │
│ 当前版本 v0.4.1                    │
│                                    │
│ 问题修复                 ← 小号、次要色、大写间距，与「同步日志」标题一致
│  • 子目录无读取权限时漏同步…       │
│  • 同步大量文件时窗口无响应        │
│                                    │
│ ────────────────────────────────── │
│                     [稍后] [立即更新]│
└────────────────────────────────────┘
```

- 去掉灰色底框，内容直接放在弹窗里，层次更轻。
- 分组标题沿用「同步日志」的样式（`font-mono text-xs uppercase tracking-wide text-text-tertiary`），条目用 `text-sm text-text-secondary`，和应用现有风格保持一致。
- 加上 `break-words`，以后即使出现长文本，也不会再撑出横向滚动条。
- 保留 `max-h-64 overflow-y-auto`，说明很长时纵向滚动。

**选型理由**：

- **不引入 Markdown 渲染库**（如 react-markdown）：说明格式完全由我们自己的脚本生成，只有「分组标题」和「条目」两种结构，十几行解析就够了，没必要为此增加几十 KB 的依赖。
- **新弹窗解析的是 2.1 转换后的格式（`• `），不解析 Markdown**：清单里只会出现这一种格式，前端不需要兼容两种格式。

### 2.3 （待确认）修正已发布的 v0.4.1 清单

v0.4.1 的 `latest.json` 已经发布，里面是 Markdown 原文。用 `gh release upload v0.4.1 latest.json --clobber` 替换成转换后的版本：

- **安全性**：updater 只校验安装包的签名，`notes` 不在签名范围内，替换说明文本不影响更新校验。
- **收益**：还在用 v0.4.0 的用户（包括你另一种安装方式的测试）马上就能看到干净的说明。
- **代价**：修改了一个已经发布的 Release 资产，需要你同意。

## 3. 影响文件

- `scripts/updater-manifest.mjs`：生成 `notes` 时做转换
- `src/components/UpdateDialog.tsx`：分组渲染
- 版本号升至 0.4.2

## 4. 验证方式

1. 本地运行清单脚本，确认 `notes` 是转换后的格式。
2. 在弹窗里注入 v0.4.1 的真实说明（转换后的格式），用 CDP 打开弹窗并截图，确认排版效果，没有横向滚动条。
3. 发布 v0.4.2 后，在 v0.4.1 的旧弹窗里看到干净的纯文本说明；更新到 v0.4.2 后，以后的更新会显示新的排版。

## 5. 待确认决策点

1. **要不要替换 v0.4.1 已发布的 `latest.json`（2.3）？** 推荐**替换**：零风险，旧版本用户立刻能看到干净的说明。
2. **这次要不要发 v0.4.2？** 推荐**发**。不发版的话，修改后的清单脚本要到下次发版才生效；2.3 只能修正 v0.4.1 这一份清单。

## 6. 实施结果（2026-11-16）

**提交**：`fcc1029`（修复）、`3dba3ce`（版本号升至 0.4.2），作为 v0.4.2 发布。

### 6.1 与方案的偏差

| 方案 | 实际 | 原因 |
|---|---|---|
| 决策点 1 推荐替换 v0.4.1 的 `latest.json` | 没有替换 | 更新器读取的是 `releases/latest/download/latest.json`，永远指向最新的 Release。v0.4.2 发布后，v0.4.1 的清单不会再被读取，替换没有意义 |
| 解析时用 `sections.at(-1)` | 改用 `sections[sections.length - 1]` | 项目 tsconfig 的 lib 低于 ES2022，`Array.at` 类型检查不通过；为一行代码改编译配置不值得 |

### 6.2 验证

- 清单脚本：v0.4.1 的说明转换后是 `问题修复\n\n• 子目录无读取权限时漏同步却显示成功\n• 同步大量文件时窗口无响应`。
- 弹窗：`tmp/harness.html` 用假的 update 对象在 vite 中渲染，agent-browser 截图（`tmp/dialog-short.png`、`tmp/dialog-long.png`）。长链接自动换行，内容区 `scrollWidth = clientWidth = 398`，没有横向滚动条。

### 6.3 踩的坑

- 无头 Edge（`msedge --headless=new --screenshot`）在本机既不报错也不生成截图，原因没有深究，改用 agent-browser 后正常。
